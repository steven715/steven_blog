# 執行緒模型備忘錄

設計新模組或跟 AI 討論並發設計時的對照表。判斷順序決定一筆狀態落在哪個模式，模式表給解法與風險。

---

## 一、判斷順序

拿到一筆可變狀態，依序回答。鎖的種類是最後的結論，不是第一個問題。

1. **寫者是誰**：哪條執行緒改它？只能有一個。有兩個名字就是設計問題。
2. **讀者有幾個、在哪**：同執行緒讀不用同步；跨執行緒讀才進下面的問題。
3. **一致性要求**：讀者能接受舊值？要跟另一筆資料同一時刻？寫完要立刻讀得到？
4. **多急**：熱路徑、業務路徑、背景。
5. **生命週期**：舊版本被換掉後誰回收？讀者握著指標時物件會不會消失？
6. **背壓**：生產者快過消費者時，佇列長度誰管、滿了丟誰？
7. **半途失敗**：持鎖時 throw、事件處理到一半 crash，狀態停在哪？
8. **重入**：callback 會不會回頭呼叫發出它的模組？
9. **時間所有權**：timer 回呼跑在哪條執行緒？這會不會變成第二個寫者？
10. **啟停順序**：執行緒起來時資料就緒了嗎？關閉時佇列要排空嗎？

前四題決定模式，後六題決定模式之外還要補什麼。

---

## 二、模式表

| 場景 | 解法 | 主要風險 |
|---|---|---|
| 可變業務狀態（持倉、委託、狀態機） | 單寫者執行緒 + 事件送入 | 跨執行緒查詢要走事件或快照 |
| 讀多寫少的大資料（配置、合約表結構） | 不可變快照 + 指標交換 | 舊版本回收時機。C++14 的 `atomic_load(shared_ptr)` 走全域鎖池，不是無鎖；要無鎖得用裸 atomic 指標 + 延遲回收 |
| 高頻單筆最新值（每合約報價） | seqlock 或 16-byte atomic 交換 | 讀者要的是單筆撕裂保護，不是全市場一致；整張 map 做快照是 O(N)/tick，方向錯 |
| 1:1 熱路徑 | SPSC ring，不走 EventBus | 無背壓就是延遲炸彈 |
| 按 key 分片、片內有序、片間平行 | hash(帳戶) → 固定 worker；片內 FIFO | 跨 key 操作打破模型：路由到同一片，或寫 saga |
| 阻塞 I/O 要結果回來 | 丟輔助執行緒池，完成後以事件送回擁有者 | 回來時擁有者狀態已變，要帶版本號或 correlation id |
| 跨執行緒同步查詢 | 讀快照 / 送查詢事件等回覆 / 擁有者定期發布唯讀視圖 | 快照有 read-your-writes 問題，要加水位版本號 |
| 一對多廣播、消費者快慢不一 | 每消費者一條佇列；慢的 conflate 或踢掉 | 共享佇列被最慢的拖垮 |
| 多寫者、低讀、最終一致（計數、統計） | 每執行緒分片計數，讀時聚合 | 分片沒 padding 到 64 bytes 的 false sharing。競爭來自多執行緒對同一行做 RMW，relaxed 一樣鎖匯流排 |
| 跨所有狀態的一致性聚合 | 世代（epoch）編號，聚合者只讀同世代 | barrier 只解「輪內齊全」，不解「同一時刻」 |
| 多模組必須原子生效的變更 | 版本化配置，各模組在下個事件邊界採用，log 帶版本 | 真原子等於 stop-the-world，通常不值得 |
| 共享資源單一所有者（socket） | I/O 執行緒擁有，其他人 post 請求，回包按序號分發 | 兩個執行緒直接寫同一 socket 會交錯封包 |
| timer 與排程 | 擁有者執行緒自己跑 timer wheel | 獨立 timer 執行緒 = 多一個寫者 |
| 快取與失效 | read-through + 單一失效路徑 | 保底會遞迴：記憶體沒有、下一層也沒有時誰負責 |
| 多階段 pipeline、速率不同 | 有界佇列 + 明確丟棄策略 | 可丟與不可丟的資料走同一條 pipeline 要兩種策略 |
| 撤單與新單的順序 | 按帳戶分片 + 片內 FIFO；撤單只對尚未送出的單做本地撤 | 分車道（兩條佇列）會讓撤單超車自己要撤的新單 |
| 跨進程共享 | 單筆最新值：共享記憶體 + seqlock；串流：SPSC ring + 心跳偵測對方存活 | 跨進程 mutex 有 `PTHREAD_MUTEX_ROBUST` 可解死鎖，但拿回鎖時資料可能寫到一半 |
| 外部事件源（kafka） | 按 (key, 序號) 去重；啟動時 load snapshot + replay offset；就緒閘門後才開始處理 | at-least-once 下重複事件 → 狀態翻倍；重啟時 snapshot 與 offset 之間的缺口 |
| 可重放的確定性狀態 | 狀態機只吃事件，時間與亂數當事件注入 | handler 裡呼叫 `now()` 就不能重放 |

真正需要「協定」而不只是「結構」的兩列：跨 key 原子操作、全狀態一致聚合。這兩列才需要 ADR。
