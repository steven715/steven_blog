## 邊界設計

- 資料結構（struct/record）不包含業務邏輯。
- 業務物件不暴露內部資料結構。
- 一個業務物件只負責一個明確的業務域，不做跨域操作。
- 模組間互動僅透過介面（callback、事件、抽象），不直接持有對方實例。

## 錯誤處理

- 偏好明顯的失敗而非隱性的錯誤。
- 狀態機中對競爭寫入事件採用 first-in-wins 搭配終端狀態，不做合併。
- 寫入操作限制為單一維度，限縮錯誤影響範圍。

## 產品化標準

一個系統被視為「產品化完成」的判斷標準：
一個有能力但不熟悉本系統的工程師，能在合理時間內接手運維與演進。

這要求：
- 知識存在於系統與文件中，而非人的腦中。
- System Narrative + Design Doc + ADR + 互動圖 + 測試共同構成接手所需的完整資訊。
